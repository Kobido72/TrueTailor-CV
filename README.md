# TrueTailor CV

כלי בקובץ HTML יחיד שמתאים קורות חיים קיימים למודעת דרושים ספציפית. רץ כולו בדפדפן, בלי שרת ובלי build step. הקריאות היחידות החוצה הן ל־Google Gemini API עם מפתח שהמשתמש מספק.

גרסה נוכחית: **v27.0**

## מפת הקבצים

| קובץ | תפקיד |
|---|---|
| `TrueTailor_CV_v27.html` | האפליקציה. 7,184 שורות. זה הקובץ שרץ. |
| `docs/TrueTailor_CV_Project_Dossier.md` | תיק הפרויקט. ארכיטקטורה, עקרונות מוצר, מודל נתונים, יומן גרסאות, פערים ידועים. נועד להיטען ל־Project Knowledge. |
| `docs/TrueTailor_CV_Project_Instructions.md` | הוראות התנהגות למודל. נועד להדבקה בשדה Instructions של הפרויקט. |

## הרצה

פתיחת `TrueTailor_CV_v27.html` בדפדפן. אין התקנה.

בשימוש ראשון נדרשת הדבקת מפתח Gemini API. המפתח נשמר ב־`localStorage` לפי מקור הקובץ, כלומר פתיחה של הקובץ מתיקייה אחרת דורשת הדבקה מחדש.

נדרשת גישה לרשת בטעינה ראשונה: הקובץ מושך Tailwind, גופנים Heebo ו־Assistant, JSZip, Mammoth ו־pdf.js מ־CDN.

## עבודה על הקוד

לפני כל משימה טכנית: קריאת תיק הפרויקט. סעיף 2 בתיק מגדיר את עקרונות היושרה של המוצר, וסעיף 6 מפרט את מנגנוני ההגנה שיושבים בקוד ולא בפרומפט.

שני כללים שנשברו בעבר וכתובים בתיק:

1. סדר גיליונות הסגנון. ה־CDN של Tailwind מזריק את הגיליון שלו ל־head בזמן ריצה, אחרי בלוק ה־style של הקובץ. כלל שחייב לנצח נכתב כ־`html body` או נושא מחלקה.
2. `.tt-page`, משתני התבניות וצינור הייצוא מזינים יחד את התצוגה, את ה־Word ואת ה־PDF. שינוי באחד מפצל את שלושתם.

בכל מסירה: עדכון `TT_VERSION` (שורה 865) ועדכון סעיף 9 בתיק.

## מצב בדיקה

מה שנבדק בעת סידור התיקייה: הקבצים הועתקו בלי שינוי, `TT_VERSION` הוא `v27.0`, וכל הפונקציות שהתיק מזכיר כפונקציות מפתח קיימות בקובץ.

מה שלא נבדק: ריצה מול Gemini API, ייצוא Word וייצוא PDF. לפי סעיף 10 בתיק אלה לא נבדקו מאז v25.8.
